# Code of Conduct

ResolveOps is an engineering project built around reviewable evidence and clear technical disagreement. Participation should make the project safer, more accurate, and easier to inspect.

## Expected behavior

Contributors and maintainers are expected to:

- discuss technical decisions with specificity and evidence;
- critique code, designs, tests, and claims rather than people;
- disclose uncertainty and limitations instead of overstating validation;
- protect credentials, private customer information, and non-public security details;
- respect review decisions and use documented escalation paths when disagreement remains;
- keep security reports private until disclosure is appropriate.

## Unacceptable behavior

The following are not acceptable in project spaces:

- harassment, discrimination, threats, or personal attacks;
- deliberate publication of credentials, customer data, or other private information;
- knowingly misleading claims about security, validation, or production readiness;
- attempts to bypass review or safety controls for high-impact changes;
- spam, sustained disruption, or bad-faith participation.

## Enforcement

Maintainers may edit or remove comments, reject contributions, restrict participation, or take other proportionate action when behavior conflicts with this policy.

For ordinary project questions, use GitHub issues. Security vulnerabilities or sensitive reports should be sent privately to the repository owner as described in [`SECURITY.md`](SECURITY.md).
